# Локальный AI-ассистент по коду (qwen + Ollama) — подробный план настройки

Гайд: как на **своей машине** склонировать jWorkPlace (или любой проект) и работать с ним через
**локальную LLM** — с чатом по коду **и** автодополнением, полностью офлайн. Плюс готовые
**файлы правил** (глобальный + проектные), адаптированные под небольшую локальную модель, и разбор
**как настраивать саму модель** (что видит, сколько контекста, temperature, top_p).

> TL;DR стек: **Ollama** (движок) + **qwen2.5-coder** (модели) + расширение **Twinny** (проще) или
> **Continue** (гибче) в **VS Code**. Правила — короткие, директивные (маленькая модель ≠ Opus).
>
> **ОС: Windows.** Все команды ниже — в **PowerShell** (жми `Win`, набери «PowerShell»). Ollama на
> Windows работает как фоновое приложение в трее, а не как systemd-сервис.

---

## 0. Модель мышления: два слоя, нужны оба

| Слой | Что делает | Варианты |
|---|---|---|
| **Движок** | запускает LLM, отдаёт HTTP-API | **Ollama** (проще всего) или LM Studio |
| **Расширение IDE** | чат + автокомплит в редакторе, ходит в движок | **Twinny** (проще) или **Continue** (гибче) |

LM Studio — это движок (+ свой GUI-чат), **не** автокомплит в редакторе. Для «чат + автокомплит в
коде» нужен движок **и** расширение. Ниже — на Ollama (ты его уже знаешь по jWorkPlace).

---

## 1. Требования к машине и выбор размера модели

Автокомплит срабатывает на каждый набор символов → модель должна быть **маленькой и быстрой**. Чат
может быть крупнее. Ориентир по свободной памяти (RAM для CPU / VRAM для GPU):

| Память | Чат-модель | Автокомплит-модель |
|---|---|---|
| ~8 ГБ | `qwen2.5-coder:3b` | `qwen2.5-coder:1.5b-base` |
| ~16 ГБ | `qwen2.5-coder:7b` | `qwen2.5-coder:1.5b-base` |
| 32 ГБ+ / хороший GPU | `qwen2.5-coder:14b` | `qwen2.5-coder:3b-base` |

Почему `qwen2.5-coder`: сильная модель под код, **32K контекста нативно** (до 128K с YaRN),
встроенная поддержка **FIM** (fill-in-the-middle) — то, что нужно для автокомплита.

⚠️ **Автокомплит-модель — обязательно `-base`, не instruct.** FIM живёт в base-версии; instruct будет
«болтать» вместо вставки кода.

## 2. Шаг 1 — Ollama и модели

**Предпосылки (Windows), ставятся через winget в PowerShell:**
```powershell
winget install Ollama.Ollama                 # движок LLM
winget install OpenJS.NodeJS.LTS             # Node (для frontend/расширений)
winget install Python.Python.3.12            # Python (для backend)
winget install Git.Git                        # git
winget install Microsoft.VisualStudioCode    # редактор
```
После установки Ollama запустится в трее и поднимет API на `http://localhost:11434`. Проверка:
`ollama --version`. (GPU NVIDIA подхватывается автоматически, если есть CUDA-драйвер.)

**Модели (пример под 16 ГБ):**
```powershell
ollama pull qwen2.5-coder:7b           # чат/правки (instruct)
ollama pull qwen2.5-coder:1.5b-base    # автокомплит (FIM)
ollama pull nomic-embed-text           # эмбеддинги для индексации кодовой базы (@codebase)
```

### Критично: поднять контекст (`num_ctx`)

**Ollama по умолчанию даёт всего 2048–4096 токенов контекста**, даже если модель поддерживает 128K.
Из-за этого чат «забывает» файлы. Подними явно одним из способов:

**A. Глобально (env-переменная):**
```powershell
setx OLLAMA_CONTEXT_LENGTH 16384    # запишется в переменные окружения пользователя (навсегда)
```
⚠️ `setx` действует для **новых** процессов. Чтобы применить: правой кнопкой по иконке Ollama в трее →
**Quit**, затем запусти Ollama заново (иначе движок продолжит работать со старым значением).
(Альтернатива через GUI: `Win` → «Изменение переменных среды текущего пользователя» → добавить
`OLLAMA_CONTEXT_LENGTH=16384`.)

**B. Отдельной моделью с зашитым num_ctx (рекомендую для чата — не трогает автокомплит):**
```powershell
# см. Modelfile.qwen-chat в этой папке (запускать из корня клонированного репо)
ollama create qwen-chat-16k -f docs\local-qwen-assistant\Modelfile.qwen-chat
```

**C. Пер-запрос** — многие расширения умеют слать `options.num_ctx` (в Continue — поле `contextLength`).

> ⚠️ Больше контекст = больше KV-cache. Если он не влезает в VRAM — Ollama сгружает в RAM и скорость
> падает в 20–50× (с 50–100 tok/s до 2–5). Если после подъёма `num_ctx` всё резко затормозило —
> ты вышел за бюджет памяти, уменьши `num_ctx` или модель.

## 3. Шаг 2 — расширение в VS Code

### Вариант A — Twinny (проще, быстрый старт)
1. VS Code → Extensions → установить **Twinny**.
2. Сайдбар Twinny → **Manage providers**: есть дефолтные провайдеры `chat` и `fim` на Ollama
   (`localhost:11434`). Впиши свои модели: chat → `qwen2.5-coder:7b`, fim → `qwen2.5-coder:1.5b-base`.
3. У FIM-провайдера проверь **FIM template = qwen** (иначе автокомплит выдаёт мусор — см. §6).
4. Готово: автокомплит inline, чат в панели.

### Вариант B — Continue (гибче, конфиг-файлом)
1. VS Code → Extensions → установить **Continue**.
2. Скопируй пример `docs\local-qwen-assistant\continue-config.yaml` в
   `%USERPROFILE%\.continue\config.yaml` (т.е. `C:\Users\<ты>\.continue\config.yaml`) и правь под свои модели.
   Создать папку при необходимости: `mkdir $env:USERPROFILE\.continue\rules -Force` в PowerShell.
3. Правила проекта Continue подхватит из `.continue/rules/` в репозитории автоматически (см. §4).

**Что выбрать:** Twinny — если цель «быстро получить чат+автокомплит и тыкать модели». Continue — если
захочешь агентные многофайловые правки, MCP, тонкую настройку и индекс кодовой базы `@codebase`.

## 4. Шаг 3 — файлы правил (глобальный + проектный)

Смысл тот же, что у нашего `CLAUDE.md`, но **правила для маленькой локальной модели пишутся иначе**:
- **Коротко и директивно.** 7B-модель не удержит многостраничную иерархию с нюансами. Цель ≤ ~500
  токенов на файл — иначе правила съедят контекст и качество упадёт.
- **Конкретика, не абстракции.** «Импорты только `from app...`», а не «следуй архитектурным принципам».
- **Формат вывода в явном виде.** Маленькая модель любит «болтать» — скажи «дай код/дифф, минимум прозы».
- **Без оркестрации/субагентов** — локальная модель этого не делает.

Готовые файлы в PR:
- **Глобальный** (как ты работаешь везде): `docs\local-qwen-assistant\rules\global-rules.md` →
  скопировать в `%USERPROFILE%\.continue\rules\00-global.md` (Continue) **или** вставить в System Prompt Twinny.
- **Проектный** (инварианты jWorkPlace, дистиллят из `CLAUDE.md`): уже лежит в репо как
  `.continue/rules/00-jworkplace-general.md` + `10-backend.md` + `20-frontend.md` — Continue
  подхватит их автоматически при работе в этом репозитории (frontmatter `globs` scoped'ит backend/
  frontend-правила по путям, как наши L3). Для Twinny — вставь их суть в System Prompt вручную.

Continue грузит правила из `.continue/rules/*.md` в лексикографическом порядке (`00-`, `10-`, `20-`),
проектные перекрывают глобальные — ровно как наши L0 → L2 → L3.

## 5. Настройка модели: что видит, контекст, temperature, top_p

### 5.1 Что «видит» модель (контекст)
| Режим | Что попадает в модель | Как расширить |
|---|---|---|
| **Автокомплит (FIM)** | префикс+суффикс вокруг курсора в текущем файле (+ сниппеты соседних открытых файлов) | держи окно небольшим — важнее скорость |
| **Чат** | открытый файл + выделение + то, что ты явно добавил: `@file`, `@folder`, `@codebase` (RAG-индекс по эмбеддингам), `@docs` | для «изучить проект» включи индекс кодовой базы на `nomic-embed-text` |

Практика: маленькая модель ≠ «прочитает весь репо». Явно подавай нужные файлы (`@file`) или включи
`@codebase` (Continue проиндексирует репо эмбеддингами — тем же `nomic-embed-text`, что в jWorkPlace).
Это ровно разница твоего продукта: jWorkPlace делает **grounding по индексу**, а голый ассистент видит
лишь открытые/упомянутые файлы.

### 5.2 Рекомендованные параметры по ролям

| Параметр | Автокомплит (FIM) | Чат / правки | Почему |
|---|---|---|---|
| `num_ctx` | 4096 | 16384 (до 32768 если память позволяет) | автокомплиту не нужен большой контекст → быстрее; чату нужен, чтобы видеть файлы |
| `temperature` | **0.1** (можно 0.0) | **0.2** (0.4–0.7 только для «побрейнштормить/поизучать») | код — детерминированная задача; низкая temp = меньше мусора/галлюцинаций |
| `top_p` | 0.9 | 0.8–0.9 | отсекает маловероятный хвост; для кода держим уже |
| `top_k` | 40 | 20–40 | ограничивает выбор токенов |
| `repeat_penalty` | 1.05 | 1.05–1.1 | против зацикливания; выше 1.1 вредит коду |
| `num_predict` (max out) | 128–256 | 1024–2048 | автокомплиту длинный вывод не нужен |

Пояснение по крайним значениям:
- **temperature 0** для автокомплита — самый «предсказуемый» код, но иногда однообразный; 0.1–0.2 —
  хороший баланс. Для чата 0.2 = точность; поднимай к 0.7 только когда осознанно хочешь вариативности
  (изучаешь, как модель «думает»).
- **top_p и temperature регулируют одно и то же (случайность) с разных сторон** — меняй что-то одно,
  не оба сразу, иначе тяжело предсказать эффект. Для кода: фиксируй `top_p≈0.9`, играй `temperature`.

## 6. Проверка и типовые грабли

1. **Автокомплит выдаёт болтовню/мусор, а не код** → неверный **FIM-шаблон** или instruct-модель
   вместо `-base`. Возьми `qwen2.5-coder:*-base` и FIM template = qwen.
2. **Чат «забывает» файлы / обрывается** → маленький `num_ctx` (дефолт 2048). Подними (§2).
3. **Резко всё затормозило после подъёма контекста** → KV-cache вышел за VRAM, сгрузился в RAM.
   Уменьши `num_ctx` или модель.
4. **Медленный автокомплит** → модель великовата для роли; возьми 1.5B-base, `num_ctx` 4096,
   `num_predict` ≤256.

## 7. Работа под jWorkPlace (пример)

```powershell
git clone https://github.com/Eloyan19/jWorkPlace.git; cd jWorkPlace
# backend (venv на Windows — папка Scripts, не bin; активаторы .ps1/.bat, бинари .exe)
python -m venv backend\.venv
backend\.venv\Scripts\pip.exe install -r backend\requirements.txt
# frontend
cd frontend; npm ci; cd ..
code .    # откроется VS Code; Continue подхватит .continue\rules\*
```
> Если PowerShell блокирует активацию venv (`.venv\Scripts\Activate.ps1`) — один раз выполни
> `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`. Активация не обязательна: можно звать
> `backend\.venv\Scripts\python.exe` напрямую.
В Continue включи индекс кодовой базы (`@codebase`) — и спрашивай «где вызывается X», «что делает
модуль Y». Правила из `.continue/rules/` уже задают инварианты (fail-closed, `to_thread`, `api.ts`,
секреты в env), так что локальная модель будет предлагать правки в стиле проекта, а не «в вакууме».

Источники фактов гайда — см. `SOURCES.md` в этой папке.
