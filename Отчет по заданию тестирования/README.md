# Отчёт по заданию «Два уровня тестирования»

Папка — отчётность по заданию: **как устроено тестирование jWorkPlace**, что покрыто, и
**доказательства прогонов** (скриншоты UI-смоука). Обновляется прогоном тестов.

---

## Что построено — два уровня

| Уровень | Что | Инструмент | Где |
|---|---|---|---|
| **Level 1 — код** | unit/integration на бизнес-логику, офлайн и замокано (без сети/LLM/Ollama) | pytest (backend) · vitest (frontend) | `backend/tests/` · `frontend/src/__tests__/` |
| **Level 2 — UI-smoke** | агент сам «протыкивает» реальный UI: клики, формы, проверка результата, скриншот на каждом шаге | Playwright (chromium) | `frontend/e2e/smoke.spec.ts` |

Оба уровня **встроены в flow разработки** тремя способами:
1. **Локально/в диалоге:** команда `/post-pr-check` (+`--refresh` = «задеплоил фичу → обнови smoke → прогони всё») гоняет оба уровня и собирает сводный отчёт. Определение — `.claude/commands/post-pr-check.md`.
2. **Напоминание после PR:** hook `.claude/hooks/post-pr-smoke.sh` срабатывает на `gh pr create`.
3. **CI на каждый PR:** workflow `.github/workflows/pr-tests.yml` — job `code-tests` (облако, автоматически) + job `ui-smoke` (self-hosted раннер на VPS, где есть Ollama/DeepSeek/индексы) со скриншотами в артефактах.

## Как это работает (для проверяющего)

**Level 1 — почему офлайн и надёжно.** Тесты не ходят в сеть: `conftest.py` поднимает временный
`JWP_DATA_DIR`, а LLM/эмбеддинги/git мокаются (`monkeypatch`). Поэтому они детерминированы и зелены
в чистом CI без Ollama/DeepSeek. Это доказано сквозным прогоном: первый CI-прогон честно упал на
не-герметичных местах (async-тесты без `pytest-asyncio`, скан без `gitleaks`, тест без мока сети) —
все три починены (см. историю PR #9).

**Level 2 — как агент «протыкивает» UI.** Playwright запускает `npm run dev` (Vite) и открывает
реальные страницы в chromium (headless). Каждый сценарий кликает настоящие кнопки и заполняет формы
(`getByRole`/`getByPlaceholder`, `.click()`, `.fill()`), ждёт **отрендеренный** результат и делает
скриншот на каждом шаге (файлы `S<номер>-<шаг>-<что>.png`). Стенд — локальный dev, проксирующий
`/api` на живой backend `:8200` (там Ollama/DeepSeek/индексы), поэтому S3/S4/S6 показывают реальные
поиск/чат/базу знаний, а не заглушки.

## Как запустить

```bash
# Level 1
cd backend  && .venv/bin/python -m pytest -q
cd frontend && npx vitest run

# Level 2 (сам поднимет Vite, скриншоты в frontend/e2e/screenshots/)
cd frontend && npx playwright test --reporter=list

# Оба разом + сводный отчёт
/post-pr-check                # в Claude Code
```

Скриншоты в `smoke-screenshots/` — снимок последнего успешного прогона (S1–S6, по шагам).
