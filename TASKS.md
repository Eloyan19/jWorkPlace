# TASKS.md — пул задач для автономного execution-loop

> Эксперимент: ассистент берёт задачу → выполняет → (фича: PR+merge / прочее: commit) → следующая.
> Без вмешательства пользователя. Профиль выбирается автоматически по типу задачи.
> Источник правды прогресса (устойчив к компактизации). Метрики — в [`METRICS.md`](./METRICS.md).
> `plan.md`/`PLAN.md` в рамках этого эксперимента НЕ трогаем.

## Легенда
- Тип: `bug` · `feature` · `refactor` · `tests` · `docs`
- Статус: `[ ]` не начата · `[~]` в работе · `[x]` сделана · `[!]` сломалась (см. METRICS.md)
- Профиль: P1 фича · P2 баг · P6 дока/конфиг · P7 research
- Флоу: **feature** → ветка+PR+merge+прогон тестов; **прочее** → commit в master (+ `/code-review` при 2+ файлах логики)

## Тема эксперимента
Реорганизация «раздутого» набора вкладок сервиса + уборка техдолга + недостающие тесты + доки.
Основано на карте UI (frontend/src/App.tsx:14-21): 6 вкладок, назначение нигде не подписано,
«Правки» = две панели стопкой без переключателя, «Поддержка» стоит среди репо-вкладок хотя сервисная,
активная вкладка не персистится.

**Статус:** [x] done (проверено, изменение не нужно).
