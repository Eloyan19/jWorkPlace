# experiments/ — сводка треков: дешёвый инференс под контролем качества

Четыре учебных сайдкара в этой папке — не разрозненные опыты, а **одна линия**: как получать
надёжный структурированный ответ, не доплачивая за это лишнего. Все решают **одну задачу**
(триаж/классификация тикета поддержки jWorkPlace) на **одном тест-сете** (20 входов: `correct` /
`borderline` / `noisy`, с prompt-injection и off-topic внутри), на **одной модели** (`deepseek-v4-flash`,
+ `deepseek-v4-pro` в routing), через **общее ядро** `confidence/confidence_harness.py` (HTTP, ключ,
строгая схема, прайс). `microfirst` добавляет к этому **нижний, не-LLM уровень** (embedding-классификатор
на локальном nomic). Поэтому их числа сопоставимы, а выводы складываются.

> Детали и теория каждого — в его `EXPLAINER.md`/`README.md`. Здесь — что каждый показал, чем они
> отличаются и **как комбинируются в один прод-каскад**.

---

## 1. Четыре трека = четыре ортогональные оси одной проблемы

| Трек | Отвечает на вопрос | Ось |
|---|---|---|
| [`confidence/`](./confidence/README.md) | «Насколько модель **уверена** в этом ответе?» | **измерение** качества (знать, когда не уверен) |
| [`routing/`](./routing/EXPLAINER.md) | «**Какой моделью** отвечать — дешёвой или дорогой?» | **выбор модели** (эскалация по трудности) |
| [`decomposition/`](./decomposition/EXPLAINER.md) | «**Как структурировать** сам инференс — одним запросом или цепочкой?» | **структура задачи** (разбить на этапы) |
| [`microfirst/`](./microfirst/EXPLAINER.md) | «Нужна ли **вообще** большая LLM для этого входа?» | **отсечение** до LLM (не-LLM фильтр впереди) |

Оси независимы, но **вложены по факту реализации**: `routing` построен ПОВЕРХ `confidence` (берёт его
пайплайн как одну из эвристик эскалации), `decomposition` отсылает к `routing` за идеей «разные модели
по этапам», а `microfirst` ставит перед всем этим **самый дешёвый возможный уровень — не LLM вовсе**
(embedding-классификатор). Это не параллельные приёмы, а слои одного каскада: microfirst — его вход,
routing/confidence — середина, decomposition — форма задачи.

## 2. Что показал каждый трек (числа из `report.md`)

### confidence — контроль уверенности БЕЗ fine-tuning
Три сигнала по нарастанию цены: `constraint` (строгая схема, 0 доп. вызовов) → `redundancy`
(self-consistency K=3, T=0.7, majority vote) → `self-check` (отдельный вызов-верификатор). Выход —
статус `OK` / `UNSURE` / `FAIL`.

- Статусы: **OK 17/20 (85%)**, UNSURE 3/20 (15%), FAIL 0.
- Цена контроля: **96 вызовов вместо 20** (×4.8), latency ~12.9 c/вход, ~$0.033.
- Точность majority vs gold: **8/10**; при этом **false reject 2/10** — верный ответ контроль всё
  равно увёл в UNSURE (это и есть цена надёжности).
- **Урок:** `self-check` на этом наборе дал **0 самостоятельных reject** — предельная польза ноль,
  цена реальна (+1 вызов/вход); все UNSURE родила `redundancy`. 100%-OK недостижимо без потери части
  верных ответов — порог строгости всегда компромисс.

### routing — flash по умолчанию, pro как fallback
Те же 3 эвристики как «триггер эскалации»: `length` / `constraint` (по 1 вызову flash) и `confidence`
(весь пайплайн выше). Если триггер сказал «не уверен» — переспрашиваем `pro`.

- Эскалации: `length` **0/20**, `constraint` **0/20**, `confidence` **4/20 (20%)**.
- Точность: всё-на-flash **7/10**, всё-на-pro **8/10**, routing-by-`confidence` **8/10** (догнал pro).
- Цена: всё-на-flash $0.0091 (×1.0), всё-на-pro $0.0236 (×2.6), routing-by-`confidence` $0.0374 (**×4.1**).
- **Урок:** дешёвые эвристики на робастной модели (flash + `json_object`) почти всегда **молчат** —
  явный брак редок. `confidence` — единственный, кто ловит семантическую неуверенность, но его проба
  стоит как несколько ответов. Прод-выбор — **каскад**: дешёвые фильтры всегда, дорогую пробу выборочно.

### decomposition — monolithic vs multi-stage
Одна задача-триаж двумя способами: A — 1 большой запрос (9 полей сразу); B — цепочка `stage1`
нормализация → `stage2` классификация чистой сути → `decide()` (маршрут **в коде**, 0 вызовов) +
короткое замыкание на off-topic/injection.

- Точность: A **7/10**, B **8/10**.
- Инъекция (#19): A **упал** (schema_violation, ответа нет), B **распознал** и обезвредил
  (`flag_security`) — атакующему `pr_edits/high` не досталось ни одному.
- Формат-сбои: A 3/20 (рушится весь ответ), B 2/20 (локальный этап, всегда безопасный исход).
- Маршрут: A считает LLM (0/17 нарушений, но не гарантия), B — код (**0 by construction**).
- Цена: A $0.0188, B $0.0187 (**×0.99** — на равной модели НЕ дешевле, латентность даже выше).
- **Урок:** декомпозиция покупает **надёжность / детерминизм / отлаживаемость**, а не цену. Деньги
  экономит отдельно — разными моделями по этапам + выносом жёсткой логики в код + отсечкой мусора рано.

### microfirst — micro-model first (не-LLM фильтр перед большой LLM)
Уровень 1 — nearest-centroid на эмбеддингах `nomic-embed` (локальный Ollama, **0 вызовов LLM**),
уверенность = `margin` (отрыв top1 от top2); Уровень 2 (flash) — только на `UNSURE`. Классифицирует
категорию (приоритет вне Уровня 1 сознательно — эмбеддинги слабы на оси срочности).

- Отсев микромоделью: **14/20 (70%)**, в fallback ушло 6.
- Вызовы большой LLM: **7 vs 22** у «всегда-LLM» (**−68%**), стоимость **−71%**, средняя latency
  1.34 c vs 2.46 c.
- Точность: micro-first **10/10** = базлайн **10/10** — отсекли 70% нагрузки **даром**.
- Инъекция (#19): margin схлопнулся до 0.024 → эскалация → flash с anti-injection **не поддался**.
- **Урок:** сигнал уверенности эмбеддинга — **margin, а не абсолютная близость** (nomic жмёт все
  косинусы в полосу ~0.7, off-topic «борщ» дал top1=0.73). «Micro-model» — спектр по цене
  `LLM > embedding > TF-IDF ML`; бери самый дешёвый достаточный, гейти по относительному сигналу.

## 3. Сквозные уроки (общее через все четыре)

1. **Сила сигнала ∝ его цена.** Самый информативный сигнал (семантическая уверенность через
   self-consistency) — самый дорогой везде: ×4.8 в confidence, ×4.1 в routing. Дешёвые формальные
   проверки (length/constraint) почти бесплатны, но ловят лишь вырожденный вывод.
2. **На робастной модели дешёвые проверки молчат.** `flash` + `response_format=json_object` почти
   всегда даёт непустой валидный JSON → length/constraint = 0 срабатываний. Они — страховка на случай
   деградации, а не рабочая лошадка.
3. **Контроль качества всегда имеет двойную цену:** в деньгах/latency И в **ложных отказах**
   (false reject 2/10). «Ноль ошибок» покупается потерей части верных ответов — это выбор порога, не баг.
4. **Детерминированную логику — в код, не в LLM.** Всё, что выразимо условиями (`if priority==high →
   sla=4`), считает Python: 0 стоимости, 0 нарушений. LLM оставляем только неформализуемое.
5. **Технический подводный камень:** `deepseek-v4-flash` тратит часть `max_tokens` на скрытые
   `reasoning_tokens` ДО печати JSON → при тесном бюджете пустой ответ с `finish_reason="length"`
   (ложный «обрыв»). Общее ядро лечит это одним retry с удвоенным бюджетом.

## 4. Как это собирается в ОДИН прод-каскад

Треки не конкурируют — они слои. Разумный продовый конвейер для «дешёвого надёжного структурированного
ответа» комбинирует все три оси:

```
запрос
  │
  ▼  MICRO-MODEL FIRST (microfirst): дешёвый НЕ-LLM фильтр впереди всего
  │     ├─ уверен (большой margin) → ответ БЕЗ единого вызова LLM (отсекает большинство)
  │     └─ не уверен → пропускаем вход дальше, в LLM-часть каскада
  │
  ▼  ДЕКОМПОЗИЦИЯ (decomposition): разбить на этапы, если задача многосоставная
  │     └─ жёсткие правила — сразу в КОД (decide()), не в LLM
  │
  ▼  на каждом LLM-этапе — РОУТИНГ (routing): дёшево по умолчанию (flash)
  │     ├─ дешёвые фильтры length/constraint — ВСЕГДА (почти даром, отсечь явный брак)
  │     └─ дорогая проба УВЕРЕННОСТИ (confidence) — ВЫБОРОЧНО (только где цена ошибки высока)
  │
  ▼  не уверены → ЭСКАЛАЦИЯ на сильную модель (pro), иначе ответ flash
  │
  ▼  fail-closed на каждом стыке: сбой/сомнение → безопасный исход (на человека), не наугад
```

Одной фразой: **отсеки простое не-LLM фильтром → декомпозируй остаток → дёшево по умолчанию → мерь
уверенность → эскалируй только неуверенное → жёсткую логику держи в коде → на любом сбое падай в
безопасную сторону.** Каждый трек
измерил цену и пользу своего слоя отдельно, чтобы в этом каскаде не включать дорогое там, где хватает
дешёвого.

## 5. Ограничения (общие для всех треков)

- Тест-сет мал (**20 входов**) — числа показывают **направление**, не строгую статистику.
- Прайс — **приблизительные** placeholder-константы; относительные выводы (во сколько раз дороже)
  держатся, точный биллинг — нет. Абсолютные $ между треками **не** сравнивать напрямую (разный размер
  промптов). Сравнивать — отношения ВНУТРИ трека.
- Родственный трек `experiments/finetune` (LoRA-классификатор, ветка `experiments/finetune`) — про
  **другой** способ (дообучение весов вместо контроля инференса) и другой стек (Kaggle→Qwen→GGUF), в
  этой папке кода нет; здесь он упомянут лишь как соседняя ветвь той же учебной линии.
